# 技术架构文档生成（面试向）

## 技能定位

本技能用于产出**面向面试场景的深度项目技术架构文档**。文档不是简单的代码说明，而是能够体现作者对项目「整体架构、核心链路、关键决策、权衡取舍」理解深度的面试材料。文档中每个技术点都必须配套「面试官可能追问的问题」与「该问题考察的技能点」。

> 参考范例：`docs/Technical Architecture/AI_RESUME_STREAM_ARCHITECTURE.md`（SSE 流式链路 + 时序图 + 降级策略 + 设计决策的结构范式）。

## 触发场景

当用户表达以下意图时立即使用本技能：

- 「为面试准备一份项目技术架构文档」
- 「梳理一下项目的架构 / 核心链路 / 关键技术方案」
- 「把我的项目写成能写进简历的技术亮点文档」
- 「讲解项目的架构设计思路 / 技术难点」
- 「生成系统设计 / 架构说明文档」

## 核心原则

1. **真实至上**：文档必须基于项目实际代码与真实技术选型，禁止虚构功能、数据量或复杂度（如「百万并发」「微服务」等未实际存在的表述）。
2. **链路完整**：每个核心功能必须从入口 → 处理 → 出口完整描述数据流向，而非罗列文件。
3. **决策先行**：不只写「怎么做」，更要写「为什么这么做」以及「不这么做会怎样」（体现权衡）。
4. **问答配套**：每个技术点必须附带面试问题预测 + 考察技能点映射（见下）。
5. **使用中文**：默认以中文输出（除非用户指定其他语言）。

## 工作流程

1. **收集信息**：询问用户项目名、技术栈、核心功能；若代码可访问，读取关键文件（路由/控制器、服务层、核心工具库、部署配置、package.json 等）确认细节，禁止凭空编造。
2. **确定范围**：与用户确认文档覆盖的系统边界（单模块 / 全系统）、侧重点（如某个核心链路）。
3. **梳理链路**：识别 2-5 条核心业务流程与数据流向，标注关键组件与数据形态。
4. **产出文档**：按下方「标准结构」编写，每个技术点同步产出面试问答。
5. **自检**：对照「质量检查清单」复核，重点检查：是否有真实依据、是否覆盖全部强制章节、面试问题是否与考察点一一对应。

## 文档标准结构（强制章节）

### 1. 系统概述
- 项目定位、解决的问题、面向用户
- 整体架构图：Mermaid `flowchart`（模块划分 + 组件关系 + 技术栈标注）
- 技术栈选型表：技术 | 用途 | 选型理由 | 备选方案与放弃原因

### 2. 系统架构
- 分层架构 / 模块划分（前端、后端、存储、外部依赖）
- 部署架构（若存在）：进程模型、环境变量、关键配置
- 模块间通信方式（HTTP / SSE / WebSocket / 事件 / 消息队列）

### 3. 核心业务流程与数据流向
- 每条流程：**时序图（Mermaid `sequenceDiagram`）** + 文字说明
- 标注：请求/响应数据结构、错误路径、边界条件
- 强调关键设计：如断点续传、重试、状态机、降级

### 4. 关键技术难点及解决方案
每个难点按以下模板展开：
- **难点描述**：问题背景与挑战
- **方案设计**：核心思路 + 关键代码/组件引用
- **落地细节**：实现要点（如定时器清理、竞态保护）
- **备选方案对比**：其他方案及为何放弃
- **效果**：带来的收益（量化优先，但必须真实）

### 5. 性能优化策略
- 前端：懒加载/按需导入、分帧渲染、防抖节流、缓存、构建分包
- 后端：缓存、并发控制、流式处理、索引、批处理
- 网络：SSE/流式、压缩、CDN
- 每项优化标注：优化对象 | 手段 | 收益 | 代价/权衡

### 6. 安全设计
- 认证与授权（JWT、守卫、权限模型）
- 输入校验（DTO 校验、注入防护）
- 敏感信息（密钥环境变量化、脱敏）
- 传输安全、限流/防滥用
- 其他本项目实际存在的安全实践

### 7. 扩展性考虑
- 架构上为扩展预留的机制（配置化、插件化、抽象接口、事件钩子）
- 未来演进方向（可选的规模化路径），明确标注为「规划」而非「已实现」
- 扩展时可能引入的新问题与解决思路

### 8. 面试问答预测（贯穿全文或独立附录）
- 为第 3-7 章中**每个技术点**产出问题预测
- 格式：**问题** → **考察点** → **参考回答要点**（答题角度 + 关键论据）

## 面试问题预测规范

对文档中每个技术点（如「SSE 断线续传」「退避重连」「状态机」「分帧渲染」「超时/取消信号组合」）按以下映射产出：

| 考察方向 | 典型问题示例 | 考察的技能点 |
|---|---|---|
| 原理追问 | 「为什么用 SSE 而不是 WebSocket？」 | 通信协议选型、HTTP 语义理解 |
| 实现细节 | 「seq 去重是怎么做的？重连会丢消息吗？」 | 事件驱动设计、容错设计 |
| 边界情况 | 「如果 LLM 超时/未配置会怎样？」 | 降级策略、容错思维 |
| 权衡取舍 | 「为什么重试只重试 1 次？」 | 成本与可靠性平衡 |
| 架构理解 | 「会话为什么要在服务端缓存事件？」 | 无状态/有状态设计权衡 |
| 优化追问 | 「高并发下打字机渲染会卡吗？」 | 性能优化、主线程友好 |

**输出格式**（每个技术点）：

```markdown
#### 技术点：<名称>
- **可能被问**：
  1. <问题> —— 考察：<技能点>
  2. <问题> —— 考察：<技能点>
- **参考回答要点**：<2-4 条关键论据，引导面试者如何组织回答>
```

## 质量检查清单

- [ ] 所有架构/数据量/性能描述均有真实代码或配置依据
- [ ] 覆盖全部 8 个强制章节
- [ ] 至少 1 张系统架构图 + 每条核心流程 1 张时序图（Mermaid）
- [ ] 每个技术难点都有「方案 + 备选对比 + 权衡」
- [ ] 每个技术点都有面试问题预测与考察点映射
- [ ] 明确区分「已实现」与「规划中」
- [ ] 文档语言与用户要求一致，代码引用使用相对路径
