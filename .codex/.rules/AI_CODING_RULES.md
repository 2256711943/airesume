# AI_CODING_RULES.md

## 1. 任务边界


- 接口以 `OPENAPI.yaml` 为准。
- SSE 事件协议以 `API_STREAM_SPEC.md` 为准。


## 2. 代码变更要求

- 每次改动需说明：变更内容、影响范围、验证结果。
- 未执行测试时必须给出原因。
- 新增公共函数、类、方法前需有简洁的中文注释说明意图。

## 3. 禁止项

- 禁止提交密钥、令牌或敏感数据。
- 禁止绕过 DTO 输入校验。
- 禁止吞掉异常且不返回可读错误信息。
- 禁止保留临时调试代码进入主分支。

## 4. 输出要求（每次 AI 回答至少包含）

- 本次改动内容
- 受影响模块
- 已执行验证
- 剩余风险或后续建议

## 5. 文件编辑策略

- 在非必要情况下，不要删除整个文件后再重写。
- 优先基于原有代码做局部修改，只删除或替换需要变更的部分。
- 只有在整文件重写明显更安全、更简单或能显著降低维护成本时，才允许整文件替换，并需在结果说明中明确原因。

## 6. 编码规范

- **严格 TypeScript**: 所有变量、参数、返回值必须有明确的类型定义，**禁止**使用 `any`。
- **文档先行 (Documentation First)**: 生成代码时，必须包含标准的 JSDoc/TSDoc 注释。
  - **组件**: `<script setup>` 顶部需包含 `@description` 说明组件用途。
  - **Props**: `defineProps` 上方需说明每个属性的业务含义。
  - **逻辑函数**: 所有函数必须包含 `@param` 和 `@returns` 说明。
- **重构触发器**: 当发现自己在"复制粘贴"代码时，**立即停止**。改为将公共逻辑提取到 `composables/` 或 `utils/` 中，并更新原来的引用。
