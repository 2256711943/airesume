项目描述
基于 Nuxt4（Vue3 + Vite + TypeScript + Element Plus）+ NestJS（Prisma + SQLite）全栈架构开发的 AI 简历生成助手，实现简历生成，与生成过程实时可视化（同步推送、Agent 步骤与工具调用轨迹，用户边等待边直观看到 AI 的执行过程）、上下文与记忆管理、历史会话恢复、简历编辑联动实时预览、简历多模板 PDF 导出等核心功能。
项目亮点
1. 自研 SSE 分帧渲染管线，实现打字机效果，背压控制：以 requestAnimationFrame 构建 "Ingress → 转换 → 帧缓冲 → 逐帧提交" 渲染引擎，8ms 帧预算 + EWMA 帧耗时平滑，四维加权压力评分（队列深度/滞留时长/帧耗时超标/连续积压）驱动 idle~critical 五级降级（裁剪装饰性帧项、压缩帧预算至 1ms），高峰期帧耗时稳定在预算内、FPS 保持 ~60，长任务（>16ms）出现频率下降约 80%；打字机以 Intl.Segmenter 字素簇粒度分割（降级 Array.from）配合字符余量累积逐字输出，正确处理中文输入法组合字符，压力高时降速、遇终止项立即冲刷，降级不丢内容；以状态机统一管理 SSE 生命周期，超时检测 + 自动重试保证全程可中断、可恢复、可追踪，一次约 10 分钟 / 3 万字长流无中断、无丢失。
2. 落地分层上下文与记忆管理，构建可解释的 Context Pack，解决 "长会话 token 膨胀" 与 "记忆取舍不可解释" 两大痛点：相比 向量检索 RAG（召回不确定、不可预算）与 全量拼接（token 爆炸），将记忆按 system/resume/preference/tool_result/session 分层建模，自研预算管理器在 "条目数 + token" 双预算下（支持预留 token、按层覆盖限额）逐层子集选择，保证注入确定性、可预算、可追溯；每次构建产出 Context Pack，完整记录 selectedMemoryId、每条记忆被裁的精确原因与 token 统计等，取舍全程可解释、可审计；配合内存 + 持久化双存储（L1 LRU+TTL 淘汰、L2 异步落库）与摘要合并，上下文压缩率约 70%、单轮 token 成本下降约 60%，长会话（20 轮）记忆命中率保持 90% 以上。
3. 构建 Agent 链路观测、回放与故障诊断闭环：以 "run → span → event → checkpoint → diagnostic_issue" 统一组织 Agent 执行链路，事件按 run 内全局 seq 编号、spanId 关联父子关系并归一化 route_decision、tool.call、assistant_chunk、checkpoint、error 等类型；实时观测端提供运行时间线、span 树、工具调用状态与文本输出节奏，支撑 "边运行边排障"；事件日志按 P0/P1/P2 分级持久化（run_id+seq、conversation_id+ts、type+ts 多索引），SSE 断线重连后基于 seq 做事件补偿，保证数据连续可追；回放层基于 seq 与 checkpoint 锚点实现已完成 run 的单步播放、暂停、快进与定位，并支持多 run 对比定位决策差异；诊断采用规则引擎优先（覆盖路由误判、工具失败/超时、上下文缺失/重复/裁剪、流中断/未结束、Agent 循环等高频类别），每条诊断输出结构化结论并可回指事件证据，同时预留 LLM 辅助诊断接口——只消费脱敏裁剪后的结构化上下文、结果仅作补充建议不覆盖规则结论，形成 "先看清、后复盘、再增智" 的完整闭环。
4. 简历 PDF 导出服务，前端以 "模板 + 主题" 双维度解耦构建多模板设计系统：前端为本模块技术核心：模板层只声明布局，主题层只声明视觉 tokens，新增模板或主题仅追加一条配置；前端预览与后端导出共用同一份渲染数据与 HTML/CSS 单一渲染源，从架构上消除 "双实现" 导致的预览与导出一致性偏差；配套编辑联动实时预览，切换模板/主题即时重绘。
