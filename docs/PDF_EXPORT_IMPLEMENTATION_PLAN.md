# PDF 导出功能项目实施计划书

## 1. 项目概述

### 1.1 背景

当前简历产品在对话工作台中生成三版简历（技术版 / 业务版 / 综合版），以 Markdown 形式展示，导出能力仅支持导出 Markdown 文本文件。参照 `DOCUMENT_RENDERING_ENGINEERING_PLAN.md` 中"内容建模 → 模板映射 → 布局计算 → 预览/导出"的总体方向，本实施计划聚焦其中的 **PDF 导出闭环** 先行落地：让简历能以稳定、可分页、与预览一致的 PDF 文件交付给用户。

### 1.2 项目目标

- 建立一条「前端打印视图 → 服务端渲染 → PDF 文件下载」的稳定导出链路。
- 保证 PDF 与前端预览在字体、分页、段落布局上保持一致。
- 提供清晰、可诊断的失败反馈，覆盖超时、字体缺失、渲染异常等场景。
- 为后续「Resume DSL + 模板体系 + 布局引擎」演进预留清晰接口与边界。

### 1.3 范围边界（本次已对齐）

| 包含（In Scope）                                 | 不包含（Out of Scope，后续阶段另行规划） |
| ------------------------------------------------ | ---------------------------------------- |
| 服务端 PDF 生成能力（无头浏览器渲染输出）        | Resume DSL 数据结构建模与内容层重构      |
| 前端专用打印视图组件与导出交互                   | 模板切换、主题配置体系                   |
| 单版本简历的 PDF 导出闭环                        | 布局引擎 / 分页计算引擎的独立实现        |
| 导出失败诊断与基础校验（页数、字体、文本完整性） | 异步导出任务队列与 render job 状态追踪   |
| 本地环境全流程开发与联调                         | 部署环境容器化落地（本期仅输出方案规划） |
| 中文字体在本地环境的验证与规避                   | 多版本、多文档批量导出                   |

### 1.4 技术路线决策记录（本计划依据）

| 决策项             | 结论                                                  | 决策理由                                                            |
| ------------------ | ----------------------------------------------------- | ------------------------------------------------------------------- |
| PDF 渲染引擎       | 服务端无头浏览器渲染（Playwright）                    | 与前端共享 HTML/CSS，预览与导出一致性天然成立；文字可选中；分页受控 |
| 导出 HTML 提供方式 | 前端专用打印视图组件，导出时序列化组件 DOM 交给服务端 | 预览与导出的渲染来源完全同源，避免维护两套模板                      |
| 导出交互形态       | 同步即点即下                                          | 实现简单、体验直接；长文档超时风险通过超时提示与重试入口兜底        |
| 部署策略           | 本地先行，部署后置                                    | 本期先在本地环境跑通全链路，容器化与字体方案作为上线前规划项输出    |

### 1.5 术语约定

- **打印视图**：前端为导出专门提供的简历呈现视图，与对话聊天界面分离。
- **导出链路**：打印视图 → DOM 序列化 → 服务端接收 → 无头浏览器渲染 → PDF 文件流 → 前端触发下载。
- **校验项**：PDF 生成后对其页数、关键文本、字体嵌入等维度的程序化检查。

## 3. 分阶段实施计划

### 阶段一：技术预研与可行性验证

#### 3.1.1 阶段目标与预期成果

- 验证无头浏览器在本地环境可稳定生成含中文的 A4 标准 PDF（页面尺寸、页边距、打印背景正确）。
- 验证页眉页脚渲染、分页控制（条目不被切断、孤行寡行规避）、字体加载三类关键能力。
- 预期成果：**《PDF 导出技术验证报告》**，包含每项验证的结论、样例输出与问题记录。

#### 3.1.2 具体执行内容与操作要点

- 搭建本地无头浏览器运行环境，安装浏览器运行时及其操作系统依赖，确认启动正常。
- 使用一份包含中文、英文、数字混合的示例页面，验证「HTML → PDF」全流程输出正确。
- 验证页眉页脚机制：确认页眉页脚渲染在页边距区域，不与正文重叠。
- 验证分页行为：多页内容下，检查分页断点是否符合预期、条目是否被整体保留。
- 验证中文字体：确认中文正常嵌入与显示，记录字体加载失败时的表现与规避手段。
- 验证前端序列化 DOM 交付服务端渲染的可行路径（含样式是否随 DOM 完整传递）。
- **操作要点**：所有验证必须留存书面结论与样例产物；识别「本地环境」与「部署环境」的差异点清单，作为阶段五方案输入。

#### 3.1.3 所需资源与工具

- 本地开发机（与生产环境 OS 尽量一致）。
- 无头浏览器工具链（Playwright 及其浏览器下载能力）。
- 中文字体样本（系统字体与开源中文字体各一）。
- 一份标准化的示例 HTML 测试页面。

#### 3.1.4 质量检查标准与验收条件

- 本地环境可稳定重复生成含中文的 A4 PDF（连续执行多次无随机失败）。
- 页眉页脚、分页、字体三项能力各有明确验证结论与样例。
- 中文字体加载失败的规避方案已验证有效。
- 已输出「本地与部署环境差异点清单」。
- 阶段验收通过标志：M1 达成。

### 阶段二：服务端 PDF 导出能力建设

#### 3.2.1 阶段目标与预期成果

- 服务端提供稳定的 PDF 导出能力：接收前端交付的 HTML 与导出参数，输出 PDF 文件流。
- 具备浏览器实例生命周期管理与并发控制，避免资源失控。
- 具备明确的成功 / 失败 / 超时响应约定，失败信息可诊断。
- 预期成果：**导出服务模块上线（本地环境）**，接口可用性与异常路径经联调确认。

#### 3.2.2 具体执行内容与操作要点

- 设计并实现浏览器实例管理：全局复用浏览器进程，按导出任务隔离会话，避免每次导出冷启动。
- 实现导出接口：接收 HTML 内容与导出参数（页面尺寸、页边距、页眉页脚、是否打印背景等），返回 PDF 文件流。
- 实现渲染就绪等待：确保页面内容与字体加载完成后才开始输出，防止半成品 PDF。
- 实现异常与超时处理：渲染超时、浏览器异常、内容为空等场景均有明确错误响应，并记录可诊断信息（如错误分类与阶段）。
- 设计并发控制：同步导出形态下限制同时执行的导出任务数，超限时明确排队或拒绝并提示。
- 输出内容安全边界：仅接受约定的 HTML 结构，避免将服务端渲染能力开放为任意内容渲染入口。
- **操作要点**：接口契约（请求字段、响应结构、错误码约定）需先与前端书面确认，形成联调依据。

#### 3.2.3 所需资源与工具

- 现有 NestJS 服务工程。
- 无头浏览器工具链。
- 现有可观测 / 日志体系（用于导出失败与性能数据的记录与排查）。
- 联调用的模拟请求工具。

#### 3.2.4 质量检查标准与验收条件

- 接口可按契约稳定返回 PDF 文件流，页数与页面尺寸符合预期。
- 异常路径（超时、空内容、渲染失败）均返回明确错误，不产生半成品文件交付。
- 连续并发执行导出任务无崩溃、无内存失控。
- 单次导出响应时间在约定的可接受范围内。
- 阶段验收通过标志：M2 达成。

### 阶段三：前端打印视图与导出交互

#### 3.3.1 阶段目标与预期成果

- 实现「所见即所得」的简历打印视图：布局、字体、分页表现与最终 PDF 一致。
- 在现有简历工作台接入「导出 PDF」入口，点击后完成「序列化 → 上传 → 下载」的同步交互。
- 失败场景提供清晰的用户反馈与重试入口。
- 预期成果：**打印视图组件与导出入口上线（本地环境）**，端到端下载体验可用。

#### 3.3.2 具体执行内容与操作要点

- 设计打印视图组件：独立于聊天对话界面的简历呈现布局，含页眉页脚占位与分页友好的结构划分。
- 样式自包含：打印视图样式需随 DOM 完整传递到服务端渲染环境，不依赖页面运行时注入；关键排版规则（字号、行距、间距）以固定值定义，避免预览与导出偏差。
- 实现导出入口：在现有简历版本预览区域新增「导出 PDF」操作，与现有「导出 Markdown」入口并存并区分。
- 实现交互流程：点击后进入导出中状态（防重复点击），完成后触发浏览器下载；失败时展示可读错误信息与重试入口。
- 实现下载处理：接收服务端文件流并触发下载，文件名按约定生成。
- 与现有导出入口的关系处理：明确「导出 Markdown」与「导出 PDF」的职责边界，不破坏既有行为。
- **操作要点**：打印视图与导出结果需在字体、分页上做逐项对照核验；交互契约与阶段二的接口契约保持一致。

#### 3.3.3 所需资源与工具

- 现有 Nuxt 前端工程。
- 简历三版数据结构与样例数据。
- 视觉 / 交互规范（打印视图样式基线）。
- 本地联调环境（服务端与前端同机运行）。

#### 3.3.4 质量检查标准与验收条件

- 打印视图与 PDF 输出在字体、分页、段落布局上一致（逐项对照无偏差）。
- 点击导出 → 下载完成全流程顺畅，导出中状态防重复提交生效。
- 失败场景（服务端超时、内容异常）有明确提示与重试入口。
- 既有「导出 Markdown」功能不受影响。
- 阶段验收通过标志：M3 达成。

### 阶段四：质量保障与联调验收

#### 4.1 阶段目标与预期成果

- 建立导出质量的程序化校验体系，覆盖页数、文本完整性、字体嵌入、溢出风险。
- 完成端到端联调与多场景回归，输出《测试报告》。
- 预期成果：**校验体系与测试报告**，验收标准清单逐项通过。

#### 4.2 具体执行内容与操作要点

- 实现校验能力：对生成的 PDF 做程序化检查，包括实际页数与预期一致、关键字段文本完整、字体正确嵌入、无内容溢出。
- 建立样例数据集：覆盖短 / 中 / 长简历、中英文混合、特殊字符、超长字段等场景。
- 开展端到端测试：从打印视图到下载完成的完整链路回归。
- 开展异常场景测试：超时、字体缺失、内容为空、服务端异常时的表现与提示。
- 建立自动化回归用例（可重复执行），纳入现有测试体系。
- 输出《测试报告》：用例清单、执行结果、缺陷记录与修复状态。
- **操作要点**：验收标准清单需先书面定稿再执行测试；缺陷分级管理，关键缺陷清零方可进入阶段五。

#### 4.3 所需资源与工具

- 本地测试环境（前端 + 服务端）。
- 自动化测试工具与现有测试框架。
- 样例数据集（多场景简历内容）。
- 现有可观测 / 日志体系（用于缺陷定位）。

#### 4.4 质量检查标准与验收条件

- 验收标准清单全部通过（见第 6 节）。
- 关键缺陷清零，一般缺陷有明确修复计划。
- 自动化回归用例全部通过，且可重复执行。
- 《测试报告》完整输出。
- 阶段验收通过标志：M4 达成。

## 4. 边界控制与变更管理

### 4.1 范围控制

- 本计划严格限定于第 1.3 节「包含」范围内；任何「不包含」项进入本期实施前，必须经过变更评审。
- 新增需求（如模板切换、批量导出、异步任务）统一进入后续阶段池，不在本期推进。

### 4.2 变更管理

- 技术方案调整（渲染引擎、模板提供方式、交互形态、部署策略）需与需求方重新对齐并更新本计划第 1.4 节决策记录。
- 范围、里程碑、验收标准的变更需记录变更原因、影响范围与新旧基线。
- 每次变更需同步评估对质量关口（M4）与交付物清单的影响。

### 4.3 质量关口

- M1 未达成不进入阶段二；M4 未通过不进入阶段五。质量关口不可跳过或合并。

## 5. 风险识别与应对

| 风险                                                 | 影响                   | 应对措施                                                                   | 责任人              |
| ---------------------------------------------------- | ---------------------- | -------------------------------------------------------------------------- | ------------------- |
| 中文字体加载失败或嵌入异常（本地与部署环境字体差异） | PDF 中文乱码 / 豆腐块  | 阶段一专项验证；统一字体来源；字体加载完成后再输出；部署方案中固化字体方案 | 服务端负责人        |
| 无头浏览器环境差异（本地 vs 部署、依赖缺失）         | 部署后导出失败         | 阶段一输出差异点清单；阶段五方案逐项落实；保留错误阶段信息便于定位         | 服务端负责人        |
| 同步导出形态对长简历 / 复杂内容的超时风险            | 用户等待超时、体验受损 | 超时上限与明确提示；失败重试入口；监控导出耗时并沉淀到上线评估             | 前端 + 服务端负责人 |
| 预览与 PDF 渲染不一致（样式丢失、字体漂移）          | 交付质量不达标         | 打印视图样式自包含；逐项对照核验；自动化回归固化用例                       | 前端负责人          |
| 浏览器资源管理不当（会话泄漏、内存增长）             | 服务不稳定             | 实例复用与会话隔离；并发限制；退出路径清理                                 | 服务端负责人        |
| 序列化 DOM 与样式传递不完整                          | PDF 排版缺失           | 打印视图样式自包含；阶段二联调时专项验证                                   | 前端负责人          |
| 打印视图样式破坏既有聊天界面                         | 回归风险               | 打印视图独立实现，与聊天界面隔离；回归测试覆盖既有页面                     | 前端负责人          |

## 6. 质量管理体系与全局验收

### 6.1 全局验收标准（本项目级）

| 编号 | 验收标准                                                     |
