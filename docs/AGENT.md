# AGENT.md

本文件定义本仓库中 AI 编码代理（包括人类协作开发）必须遵守的执行协议。

## 1. 目标

- 在既定 PRD 和技术方案内稳定交付。
- 减少“功能漂移、接口漂移、风格漂移”。
- 保证每次代码变更可审查、可测试、可回滚。

## 2. 规范优先级（从高到低）

1. `PRD.md`
2. `OPENAPI.yaml`
3. `API_STREAM_SPEC.md`
4. `DB_SCHEMA.md` / `schema.prisma`
5. `AI_SPEC.md`
6. `EVAL_SPEC.md`
7. `CODE_STYLE.md`
8. `TEST_PLAN.md`

如果规则冲突：

- 不允许自行拍板。
- 先提出冲突点 + 给出候选方案 + 等待确认。

## 3. 必须遵守的执行规则

- 不得越过 PRD 扩展业务范围。
- 不得擅自变更接口字段、状态码、事件名称。
- 不得绕过统一错误处理和日志规范。
- 不得跳过测试直接交付。
- 不得提交未在变更说明中提到的“顺手重构”。

## 4. 每次任务的标准流程

1. 读取相关文档并确认约束边界。
2. 输出实现计划（模块、接口、测试点）。
3. 实现最小闭环，不做额外扩展。
4. 运行并记录测试结果。
5. 输出变更摘要、风险与后续建议。

## 5. 变更输出模板

- 变更目的：
- 影响范围：
- 接口变化：
- 数据模型变化：
- 测试结果：
- 风险与回滚方案：

## 6. 安全与稳定性底线

- 所有输入必须校验（长度、类型、必填、枚举）。
- 所有外部调用必须设置超时与错误兜底。
- 所有关键行为必须可观测（request_id、user_id、latency、error_code）。
- 禁止记录敏感信息明文（token、密钥、完整用户隐私数据）。
