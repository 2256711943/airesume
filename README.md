# AI 简历助手（AI Resume Assistant）

一个面向求职场景的 AI 助手项目。  
当前已完成主链路收敛，保留“登录 + AI 流式简历生成”最小闭环。

## 1. 当前阶段目标

- 4-6 周内完成简历助手 MVP
- V1 优先交付：结构化简历生成
- 采用“先文档、后代码；先小改、后大改”的渐进式重构策略

## 2. 技术栈（当前）

- 前端：Nuxt + TypeScript + Tailwind + Naive UI + ECharts
- 后端：NestJS + TypeScript + Swagger(OpenAPI)
- 数据：SQLite（开发）+ Prisma
- 缓存/队列（后续阶段）：Redis + BullMQ
- AI：OpenAI API
- 协议：HTTP + SSE（流式通道）

## 5. 下一阶段待办模块（简历项目亮点）

### 5.1 岗位定制 AI 工作描述生成器（JD 驱动）

- 业务场景：用户输入目标岗位、行业、经验年限，系统生成贴近真实 JD 的工作描述，而非通用话术。
- 技术实现思路：
  1. 对 JD 做结构化解析（职责、技能、关键词、业务目标）。
  2. 引入岗位知识库，使用 RAG 召回行业术语和表达模板。
  3. 使用函数调用或 JSON Schema 约束生成结果，输出结构化简历字段。
  4. 增加输出校验与纠偏（长度、重复度、敏感词、夸大表述检查）。
- 技术难点/亮点（可写简历）：
  - 设计 `RAG + Prompt 模板 + 结构化校验` 生成链路，提升岗位匹配度与可用率。
  - 实现 LLM 输出自动纠偏与失败重试/降级策略，提高线上稳定性。

### 5.2 AI 润色优化 2.0（多目标重写 + 自动评分）

- 业务场景：同一段经历可一键生成“专业版/结果导向版/技术深度版”，帮助用户快速挑选最合适表达。
- 技术实现思路：
  1. 并发生成多版本润色结果（异步任务或并行请求）。
  2. 设计评分器（规则分 + LLM Judge），从可读性、量化程度、岗位相关性打分。
  3. 基于评分排序返回 Top-N，并在前端展示原文与润色结果 diff。
  4. 记录用户选择行为，持续优化提示词和排序策略。
- 技术难点/亮点（可写简历）：
  - 搭建 `生成 -> 评估 -> 排序` 闭环，实现多版本自动优选。
  - 引入 `LLM Judge + 规则融合` 的质量评估体系，将主观质量转为可量化指标。

### 5.3 AI 实时纠错与一致性检查（SSE 流式）

- 业务场景：用户编辑简历时实时获得拼写、语法、表达冗余、时间线冲突等修正建议。
- 技术实现思路：
  1. 前端输入防抖 + 增量分片，后端按段落进行局部检查。
  2. 通过 SSE 推送“问题类型 + 修改建议 + 风险等级”。
  3. 结合规则引擎（时间格式、数字单位、名词词典）和 LLM 语义纠错。
  4. 对高频纠错请求做 Redis 缓存，降低调用成本和延迟。
- 技术难点/亮点（可写简历）：
  - 实现增量纠错与流式回传，优化长文本编辑体验。
  - 设计 `规则引擎 + LLM` 双通道纠错，平衡速度与纠错质量。

### 5.4 模板系统升级：简历 DSL + 一键导出 PDF

- 业务场景：同一份简历内容可切换多模板（校招/社招/技术岗），并稳定导出高一致性 PDF。
- 技术实现思路：
  1. 定义统一 `Resume DSL`，对基础信息、经历、技能、项目进行结构化建模。
  2. 解耦内容层与模板层，模板仅负责渲染。
  3. 使用服务端渲染（如 Puppeteer）导出 PDF，处理分页、字体、样式一致性。
  4. 对模板配置做版本化，便于 A/B 测试和回滚。
- 技术难点/亮点（可写简历）：
  - 设计内容与模板解耦架构，支持模板快速扩展。
  - 解决 HTML 导出 PDF 的分页与字体一致性问题，保障跨端稳定性。

### 5.5 智能分类检索（行业/岗位/经验）+ 混合召回

- 业务场景：用户可按行业、岗位、经验快速检索历史简历片段并复用，提高编辑效率。
- 技术实现思路：
  1. 入库时自动打标签（行业、岗位、技术栈、年限）。
  2. 构建关键词索引 + 向量索引（混合检索）。
  3. 查询阶段做重排（关键词匹配、语义相似度、历史使用热度）。
  4. 对高频查询结果做 Redis 缓存与失效策略管理。
- 技术难点/亮点（可写简历）：
  - 落地 `关键词检索 + 向量检索 + 重排` 的混合召回方案。
  - 通过索引与缓存优化显著降低检索延迟，提升交互体验。
